# Elevators and Escalators（电梯与扶梯）

为 Minecraft 1.21.1 制作的电梯与自动扶梯模组，使用 Architectury 共享主要代码，提供 **Fabric** 与 **NeoForge** 两种构建版本。

本模组包含可配置多楼层的玻璃轿厢电梯、玩家手工搭建的井道与框架，以及模块式自动扶梯。电梯由服务端控制移动，支持轿门、选层、呼梯、楼层队列与可绑定遥控器。模组仍在持续开发中；自动测试和双平台构建并不等于所有游戏内场景均已经实机验收。初次使用建议先在备份的测试世界中体验。

## 功能一览

### 多楼层电梯

- 通过控制器配置轿厢宽度、长度、高度、楼层编号范围、楼层间距和运行速度。
- 楼层编号支持正数与负数（不允许 0），在楼层显示屏显示当前编号；多位数和负数会使用自适应布局。
- 同一电梯最多支持 **256 个楼层**，具体上限由服务器配置控制。多个站点可以使用轿厢内楼层按钮选择，也可通过厅外面板呼梯。
- 支持多站请求、运行方向与中途停靠的调度逻辑。
- 电梯按设定速度加减速移动，运行前关闭轿门，到站后开门；门口有生物时会等待，不强行关门。
- 控制器生成粒子轮廓供建造规划参考，不会自动挖掘、填充或改造玩家建筑。

### 玻璃轿厢与井道

- 轿厢采用玻璃墙面、金属底板和顶棚、角柱与内部楼层显示屏。
- 门、墙和顶棚保留分段碰撞，让轿厢不是一个堵死内部空间的实心方块。
- 乘客可与轿厢底板、天花板和墙面交互打开控制界面。轿厢是无敌实体，不会作为生物掉血，也不能被直接攻击破坏；应通过控制器拆除。
- 轿厢的尺寸依据配置整体缩放。它不是由任意方块拼装出来的结构。
- 井道由玩家自行建造，可在轿厢通道周围搭建装饰或框架；模组会检查装配及运行路径上的阻挡，但不会替玩家建井道。

### 遥控器与呼梯

- 遥控器可以绑定电梯控制器，之后用于选择楼层或直接呼梯。
- 也可在各层使用自动生成的厅外呼梯面板。
- 遥控器操作有维度和距离限制；平台或控制器必须处于已加载状态。具体操作见下文。

### 自动扶梯

- 由多个扶梯踏步模块组成，沿阶梯路径输送乘客。
- 支持反向、红石暂停和潜行不输送。
- 踏步、坡面和扶手使用组合碰撞与渲染；并非装饰方块组成的纯贴图动画。

## 系统需求与依赖

| 项目 | 版本／要求 |
|---|---|
| Minecraft | Java Edition **1.21.1** |
| Java | **Java 21**（运行游戏及从源代码构建） |
| Fabric Loader | **0.16.14 或更高版本** |
| Fabric API | 必须安装；建议使用与 Minecraft 1.21.1 匹配的版本 |
| NeoForge | **21.1.215 至 21.1.x**；模组当前声明依赖范围为 `[21.1.215, 21.2)` |
| Architectury API | **13.0.8 至 13.x**；模组当前声明依赖范围为 `[13.0.8, 14)` |

Fabric 和 NeoForge 必须选择**对应平台**的 JAR。Fabric 依赖 Fabric API；NeoForge 使用 NeoForge 自身加载环境，不要把 Fabric API 安装到 NeoForge 实例中。Architectury API 对两个平台都需要安装。请不要同时把 Fabric 与 NeoForge 两个版本放入同一个游戏实例。

> 依赖版本以当前工程元数据为准。下载依赖时，选择明确支持 Minecraft 1.21.1 与相应加载器的发行版本。模组使用 Java 21 编译；较旧的 Java 版本无法加载。

## 安装

1. 安装 Minecraft Java 版 1.21.1 对应的 Fabric 或 NeoForge。
2. 安装 Java 21 运行环境。
3. 安装相应平台所需依赖：Fabric API（Fabric）、Architectury API（两种平台）。
4. 将本模组**对应加载器**的发布 JAR 放入游戏实例的 `mods` 文件夹。
5. 选择正确的游戏目录并启动。Fabric 和 NeoForge 分别有独立的实例、依赖和 `mods` 文件夹。

从项目构建的文件通常位于：

- Fabric：`fabric/build/libs/elevators_escalators-fabric-<版本>.jar`
- NeoForge：`neoforge/build/libs/elevators_escalators-neoforge-<版本>.jar`

安装时选择**不带** `-sources.jar`、`-dev-shadow.jar` 后缀的普通平台 JAR。模组 ID：`elevators_escalators`。

## 开始使用：电梯

### 1. 放置并配置控制器

放置电梯控制器，空手右键打开配置界面。配置内容包括：

- **轿厢宽度、长度和高度**：使用比例缩放的玻璃轿厢外观与内部尺寸。
- **最低和最高楼层编号**：支持负数，不允许楼层编号 0。
- **楼层间距**：相邻楼层垂直高度，不能小于轿厢高度。
- **运行速度**：范围为每秒 0.5 至 8 格。

确认有效配置后，设置会锁定；当前版本不能在已配置控制器上直接修改参数。需要换规格时，先依游戏内拆除流程拆除电梯，再重新设置。

**楼层编号不是高度。** 楼层号可以是 `-2、-1、1、2、3`，而其垂直位置依据楼层间距和楼层顺序计算。最低层从控制器上方开始；设置负楼层号不会自动在控制器下方挖出地下井道。

### 2. 规划和建造井道

电梯控制器配置完成之后，会在周围以粒子轮廓的形式显示必须要搭建的电梯井框架轮廓。电梯井框架要么选择**完全不建造**，要么选择**完整建造**。
电梯井框架仅要求**4个立柱**，也可以选择性的增加横梁，建造材料支持任意完整建筑方块。确认控制器显示的粒子轮廓及行程空间并自行建造井道。具体要求如下：

- 保持轿厢整个行程及轿厢高度范围内畅通，不要让实体方块侵入电梯扫掠空间。
- 井道框架应建在轿厢外侧；不要封住楼层入口和门口。
- 所有运行路径区块都应已加载。电梯遇到实体阻挡或无法安全确认行程空间时会等待，移除阻挡后才可继续。
- 在各站规划轿厢底板与外部地面的衔接，避免突兀的高度差或被门口框架挡住。

模组不会自动清障、强制加载整个井道或修改玩家搭建的支撑建筑。装配前请检查粒子轮廓中的空间。

### 3. 装配轿厢

手持 `elevators_escalators:cabin` 轿厢方块，对已配置的控制器右键进行装配。成功时会消耗一个轿厢物品（创造模式除外）。

轿厢物品也可以被直接放置为普通方块；若误放，可按普通挖掘规则回收。**误放方块不等同于已装配的轿厢实体。**

## 控制与乘坐

### 轿厢内控制

- 右键轿厢地板、天花板或墙壁打开楼层控制界面。
- 选择楼层可登记目的站；控制器根据请求和当前运行方向安排停靠。
- 菜单提供开门／关门操作；轿厢移动时不能手动操作门，门口被生物占据时不能强行关门。
- 到站后门会打开。进入或离开时请注意门口和外侧井道是否安全。

### 厅外呼梯

若装配时井道条件允许，系统会在各站生成厅外呼梯面板。右键面板呼梯的上下行按钮，服务器再根据当前轿厢位置、方向与已登记请求决定服务顺序。

### 遥控器

手持遥控器右键轿厢或控制器进行绑定。绑定后可用于查看／选择登记楼层或请求运行。对空气使用时，不同按键操作用于选择目标与启动行程；对登记楼层参考方块操作可执行对应楼层呼梯／登记。遥控器受同维度及有效距离限制，超距、跨维度或电梯未加载时不能操控。

> 若操作表现与预期不同，请查看遥控器界面或游戏内提示；控制器菜单与具体遥控键位可能随版本更新。

## 井道与轿厢

控制器的粒子预览是规划参考，不会放置真实框架。井道框架是可选建筑部分，不是自动生成的实心井道。电梯运行空间须保留足够净空，特别是顶层轿厢顶棚上方；较大的轿厢和较长行程需要相应扩大净空。

轿厢配置在装配时按整体尺寸缩放。极小尺寸可能无法容纳正常站立的玩家；极大尺寸会增加空间检查成本和区块加载要求。配置文件的安全上限为边长 64、最多 256 层，但不表示普通世界能够同时实现这些极限。总行程、轿厢高度及维度建造高度仍须相容。

## 自动扶梯

按阶梯路线放置扶梯踏步模块，并使踏步朝向一致。具体操作：
在扶梯起点处放置扶梯起点控制器，并使用扶梯端点设置工具配置起点，然后在终点处使用扶梯端点设置工具配置终点即可，
会弹出设置扶梯运行速度的窗口，设置完成之后即建造完成。建造的时候会消耗相应扶梯踏板数量，如果不够会建造失败。
完成装配／连接后：

- 站在运行扶梯上会被沿路线输送；不同路线朝向决定上行或下行。
- 对踏步右键可切换方向或者急停（遵循踏步当前状态与交互提示）。
- 为踏步提供红石信号可暂停输送；潜行可避免被输送。
- 自动生成的扶梯部件受所属控制器管理，不应当作普通建筑材料拆散回收；手工放置的部件按其方块规则处理。

扶梯由模块和路径驱动，不是原版矿车、实体乘客座椅或带真实循环阶梯动画的机械结构。建造前后请检查坡面上方净空、出口平台以及拐弯和相邻模块连接。
注意，扶梯坡度不应设置过陡或过平缓。

拆除自动扶梯仅需拆除扶梯起点控制器，之后扶梯踏板会一起掉落。

## 配置与限制

首次启动后，模组会在服务器配置目录生成 `elevators_escalators.properties`，用于调整电梯规格限制，例如：

```properties
minCabinSize=1
maxCabinSize=64
maxFloors=256
```

修改配置后需按提示重启才能生效；客户端表单限制以服务端配置为准。即使调整配置，模组代码仍设有硬安全上限：轿厢边长不超过 64，楼层数不超过 256。楼层间距最大为 256，且不能小于轿厢高度。楼层端点编号范围为 `-32767` 至 `32767`，但不包括 0。

空间检查要求路径区块可用，且会检查移动路径与轿厢顶部净空。不要把“最大支持尺寸／层数”理解为能在任何维度无条件建造；世界高度、边界、区块加载和实体碰撞都会限制实际配置。

## 安全、存档与已知限制

- 电梯暂时没有完整真实电梯所具备的认证安全系统。透明墙、轿门和碰撞可以帮助限制进出，但它不是多人服务器中可替代建筑防护的安全设施。
- 新版本在继续调整乘客承载、同步与交互逻辑。若观察到穿墙、掉落伤害或错层，请保留游戏日志和复现步骤，并先在测试世界重现。
- 扶梯在楼梯、出口和高速度运行时的表现需要结合实际搭建布局测试；应保持出口畅通并留出足够净空。
- 新增或调整功能通过自动测试及 Fabric／NeoForge 构建验证，不代表已覆盖所有显卡、服务器延迟、其他模组冲突和生存流程。
- 更换版本或迁移重要旧存档前先备份。模组 ID 延续不代表任意旧版数据结构都完全兼容。
- 管理员可用命令或其他模组强行修改世界；常规方块与实体保护无法阻止拥有相应权限的强制操作。

## 从源代码构建

### 环境

- JDK 21
- 可联网下载 Gradle 与模组开发依赖；依赖缓存齐全后可尝试离线构建
- Windows 使用项目自带的 `gradlew.bat`；Linux/macOS 使用 `./gradlew`

在项目根目录执行：

```powershell
# 编译公共模块、运行公共测试、构建两个平台
.\gradlew.bat :common:test :fabric:build :neoforge:build
```

单独构建：

```powershell
.\gradlew.bat :fabric:build
.\gradlew.bat :neoforge:build
```

Linux/macOS 可使用：

```bash
./gradlew :common:test :fabric:build :neoforge:build
```

构建成功时，发行用 JAR 位于 `fabric/build/libs/` 与 `neoforge/build/libs/`。需安装进游戏的是普通平台 JAR；`-sources.jar` 是源代码包，`-dev-shadow.jar` 是开发构建产物，均不是通常的玩家安装包。
